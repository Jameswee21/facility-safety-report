# 시설 보수 · 안전보건 신고 시스템

병원 직원이 휴대폰으로 시설 고장이나 안전 위험을 신고하면, 시설팀장이 담당자를 지정하고
담당자가 조치 후 완료 사진을 올려 마무리하는 시스템입니다.

서버 코드 없이 HTML/CSS/JS 파일만으로 동작하는 정적 사이트라서 무료 호스팅으로 운영할 수 있고,
데이터는 Supabase 무료 플랜을 씁니다.

운영 주소: `https://jameswee21.github.io/facility-safety-report/start.html`

## 화면 구성

| 화면 | 파일 | 용도 |
|---|---|---|
| **분기화면** | `start.html` | QR로 처음 들어오는 화면. 안전보건 / 시설 중 선택 |
| 시설 신고 | `index.html` | 고장·불편 신고 + 처리현황 조회 (모바일) |
| 안전보건 신고 | `safety.html` | 위험요소·아차사고 신고 (모바일) |
| 관리자 대시보드 | `admin.html` | 담당자 지정·조치관리·엑셀 (PC) |
| 신고 상세 | `view.html` | 카톡 링크로 받은 건을 바로 열람·처리 |
| 사용 매뉴얼 | `manual-staff.html`, `manual-manager.html` | 담당자용 / 시설팀장용 |

## 공용 모듈

| 파일 | 설명 |
|---|---|
| `config.js` | **설정 파일 — 앱 이름, 마스터 코드, Supabase 주소·키** |
| `storage.js` | 데이터 저장 계층 (데모 모드 / Supabase 모드 자동 전환, 시설·안전보건 테이블 구분) |
| `photo.js` | 업로드 전 사진 압축 (최대 1024px, 150KB 이하) |
| `xlsx.js` | 엑셀 생성기 (외부 라이브러리 없이 직접 생성) |

## 주요 기능

### 신고 접수

- **시설 신고**: 신고유형(3종) → 발생위치 → 발생일시 → 상황설명 → 사진첨부(필수)
- **안전보건 신고**: 사고형태(8종) → 직접겪음/목격 → 발생장소 → 발생일시 → 상황 →
  사진(선택) → 위험도(3단계) → 개선의견(선택)
  - 신고자 보호 안내, 이미 다친 경우 안내를 화면에 표시합니다.
  - 주사침 찔림, 환자 폭력을 선택하면 별도 보고 절차 안내가 자동으로 나타납니다.
- **개인정보는 수집하지 않습니다.** 연락처 입력란이 없으며, 상황설명과 사진에
  환자·직원 정보가 담기지 않도록 주의 안내를 표시합니다.
- 사진은 업로드 전에 자동 압축됩니다.

### 처리 흐름 (두 신고 공통)

```
접수(담당자 미지정) → 진행중(담당자 지정) → 조치완료(완료사진 첨부)
```

- 담당자를 지정하면 상태가 자동으로 **진행중**으로 바뀝니다.
- **카톡 업무의뢰 메시지**를 생성해 복사한 뒤 담당자에게 보낼 수 있습니다.
  메시지의 링크를 누르면 해당 건만 열리고, 그 자리에서 완료 처리까지 됩니다.
- **조치완료는 완료 사진 첨부가 필수**이며, 완료 시 조치일이 자동 기록됩니다.
- 완료된 건은 조치 전·후 사진을 나란히 보여줍니다.

### 관리자 대시보드

- 통계 카드 5개 (클릭하면 해당 목록만 필터링)
- 탭 3개: 시설 신고 / 안전보건 신고(마스터 전용) / 안전 건의함
- 상태·유형 필터, 검색, 페이지 나누기(25·50·100건)
- **엑셀 다운로드** — 기존 「점검사항 조치현황」 양식과 동일 (시설 신고)
- **새 신고 실시간 알림** — 화면 배너 + 알림음 + 바탕화면 알림 + 탭 제목 건수 표시
- 마스터 전용: 신고내용 수정, 삭제, 계정 비밀번호 관리
- 로그인 상태 유지(체크 시 브라우저를 닫아도 유지)

## 두 가지 운영 모드

### 1) 데모 모드

주소 뒤에 `?demo=1`을 붙이거나 `config.js`의 Supabase 값이 비어 있으면,
데이터가 **접속한 기기(브라우저)에만** 저장됩니다. 운영 데이터를 건드리지 않고
화면과 기능을 시험할 때 사용합니다.

### 2) 운영 모드 (Supabase 무료 플랜)

Supabase는 무료 플랜(신용카드 불필요)으로 DB 500MB + 파일 저장소 1GB를 제공합니다.

1. https://supabase.com 에서 가입 → **New Project** 생성 (region: Northeast Asia/Seoul 권장)
2. 대시보드 왼쪽 **SQL Editor** → 아래 SQL 파일 실행
3. **Project Settings → API** 에서 두 값을 복사
   - `Project URL` → `config.js`의 `supabaseUrl`
   - `anon public` 키 → `config.js`의 `supabaseAnonKey`
4. 수정한 파일을 다시 배포하면 끝

| SQL 파일 | 내용 |
|---|---|
| `supabase-setup.sql` | 최초 설치용 (시설 신고·건의함 테이블, 정책, 사진 버킷, 계정 테이블) |
| `supabase-safety.sql` | 안전보건 신고 테이블 — **신규 설치 시에도 따로 실행해야 합니다** |
| `supabase-accounts.sql` | 기존 DB에 3단계 계정·삭제 기능을 추가할 때 |
| `supabase-done-photo.sql` | 기존 DB에 조치완료 사진 컬럼을 추가할 때 |

> ⚠️ 무료 플랜은 **1주일간 접속이 없으면 프로젝트가 일시정지**됩니다.
> 대시보드에서 클릭 한 번으로 재개할 수 있으며, 주기적으로 사용하면 정지되지 않습니다.

## 배포

현재는 **GitHub Pages**로 운영합니다. `main` 브랜치에 푸시하면 1~3분 뒤 자동 반영됩니다.

Netlify Drop(폴더를 드래그 앤 드롭), Vercel, Cloudflare Pages도 그대로 사용할 수 있습니다.

### ⚠️ 파일을 수정하면 캐시 버전을 올리세요

HTML의 `<script src="app.js?v=18">` 처럼 붙은 숫자를 올리지 않으면
사용자 브라우저가 예전 파일을 계속 사용합니다. 수정한 파일마다 숫자를 1씩 올려주세요.

## 계정 체계 (3단계)

| 계정 | 비밀번호 위치 | 권한 |
|---|---|---|
| 마스터 | `config.js`의 `masterCode` | 전체 기능 + 신고 수정·삭제 + 안전보건 탭 + 비밀번호 관리 |
| 시설팀장 | DB (초기값 `2026`) | 담당자 지정, 카톡 메시지, 엑셀 다운로드, 완료 처리 |
| 담당자(공용) | DB (초기값 `1111`) | 처리현황 열람 + 완료 처리만 |

- 시설팀장·담당자 비밀번호는 마스터로 로그인 후 대시보드의 **🔐 비밀번호 관리**에서 변경합니다.
- 마스터 비밀번호는 `config.js`를 직접 수정한 뒤 다시 배포합니다.

## 보안 주의사항

- `config.js`의 **`masterCode`를 반드시 변경**하세요. 공개 저장소에 올리는 경우
  이 값과 Supabase 접속키가 그대로 노출된다는 점을 염두에 두어야 합니다.
- **Supabase 접근 정책(RLS)을 반드시 좁히세요.** 설치용 SQL은 바로 동작하도록
  읽기·쓰기를 열어둔 상태이므로, 운영에 들어가면 삭제·수정 권한을 제한하고
  비밀번호 테이블은 외부에서 읽히지 않도록 바꿔야 합니다.
- 계정 인증은 브라우저 측에서 화면을 가리는 **간이 인증**입니다. 민감한 내용을
  본격적으로 다루려면 Supabase 로그인 체계를 붙여야 합니다.
- 연락처 같은 개인정보는 수집하지 않지만, **신고 내용과 사진에 환자·직원 정보가
  담길 수 있습니다.** 사이트 주소는 원내 직원에게만 공유하기를 권장합니다.
- 신고 데이터가 들어 있는 엑셀·백업 파일과 비밀번호가 인쇄된 안내장 이미지는
  `.gitignore`로 제외되어 있습니다. 실수로 커밋하지 마세요.
